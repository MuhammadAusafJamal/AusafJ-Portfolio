## Problem

A coastal development programme that needs a public web platform and a mobile app showing
the same content. Two clients reading from one source of truth, and nobody wants to find out
in six months that they have drifted.

## Approach

The backend is Umbraco 17.5 on ASP.NET MVC with SQL Server. I built the content models and
controllers that serve both the web platform and the React Native app.

Working on both sides changed how the API got designed. The contract was written once,
against a consumer I could see, so the mobile app never had to negotiate with an endpoint
shaped for the website.

## Hard decision

One set of endpoints, or a shape per client. The web platform and the app do not want
identical payloads, and separate shapes would have trimmed what the app downloads. I went
with shared REST endpoints, so web and mobile consume one data layer and cannot drift apart.
The cost is that the app receives a few fields it does not render, which has not been a
problem at this payload size.

Built between September and October 2026, and live.
