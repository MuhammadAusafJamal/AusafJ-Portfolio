## Problem

Manual QA on a web app means clicking the same paths after every change, and the paths that get
skipped are the ones that break.

## Approach

An agent that drives a real browser session against the app, exercises the paths that matter, and
reports what it found—built in a hackathon, so the scope is one weekend's worth of automated
clicking rather than a full test suite.

## What I'd change

The name isn't final, and the agent's coverage is still whatever paths I thought to write down
that weekend, not a real spec.
